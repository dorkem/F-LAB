# 1-1.HTTP 개관
## HTTP란?
- Hypertext Transfer Protocol로 전 세계의 웹브라우저, 서버, 웹 애플리케이션은 이 프로토콜로 대화한다.
- 신뢰성 있는 데이터를 전송한다.
- 기본요소에는 Http server(웹서버), Http client(서버에게 요청하는 것)가 있다.
<br><br>

## 미디어 타입
- 인터넷은 수천가지 데이터를 다루기 때문에 HTTP는 웹에서 전송되는 객체 각각에 신중하게 MIME라는 데이터 포멧 라벨을 붙인다.
  - HTML로 작성된 텍스트 문서는 `text/html`라벨
  - plain ASCII로 작성된 텍스트 문서는 `text/plain`라벨
  - JPEG로 작성된 이미지는 `img/jpeg`라벨

<br><br>

## URI과 URN
### URI(=URL)
- Uniform Resource Identifier로 인터넷의 우편물 주소 같은 것이다.
- 특정 서버의 한 리소스에 대한 구체적인 위치를 서술한다.
  - `http://`는 URL의 제알 앞단인 Scheme(스킴)이라고 불리는데 보통 프로토콜을 서술한다.
  - `www.naver.com` 두번째 부분은 웹서버의 인터넷 주소를 서술한다.
  - `/news/header.gif` 마지막 부분은 웹 서버의 리소스를 가르킨다.
 
### URN
- Uniform Resource Name으로 콘텐츠를 이루는 한 리소스에 대해, 그 리소스의 위치에 영향을 받지않는 역할을 한다.


<br><br>

## 트랜잭션
### 메서드
- `GET`: 서버에서 클라이언트로 지정된 리소스를 보내라
- `PUT`: 클라이언트에서 서버로 보낸 데이터를 저장한 이름의 리소스로 저장해라
- `DELETE`: 저장한 리소스를 서버에서 삭제해라
- `POST`: 클라이언트 데이터를 서버 게이트웨이 애플리케이션으로 보내라
- `HEAD`: 지정한 리소스에 대한 응답에서, HTTP 헤더 부분만 보내라

### 상태코드
- `200`: 문서가 바르게 반환됨
- `302`: 다른 곳에 가서 리소스를 가져와라
- `404`: 리소스를 찾을 수 없음
- 보통 이렇게 상태코드와 "OK와 같은 `사유구절`과 함께 응답한다.

### 여러 객체로 이뤄진 웹페이지
- HTML 뼈대를 한 번의 트랜잭션으로 가져온 뒤 이미지, 그래픽 조각 등을 가져오기 위해서 추가로 HTTP 트랜잭션들을 수행함.
- 웹페이지는 하나의 리소스가 아닌 `리소스의 모음`

### 메시지
- 시작줄: 요청이라면 무엇을 해야하는지, 응답이라면 무슨 일이 일어났는지 나타냄
- 헤더: 구문분석을 위해 콜론으로 구분된 하나의 이름과 하나의 값으로 구성된다.
  - 1줄에 필드 1개, 헤더는 빈줄로 끝남(CRLF)
- 본문: 요청의 본문은 웹 서버로 데이터를 실어보내고 응답의 본문은 클라이언트에게 데이터를 반환함
  - 텍스트와 임의 이진데이터 포함(이미지, 비디오등)가능

## TCP커넥션
- 메시지가 TCP 커넥션을 통해 메시지가 옮겨지는가?

### TCP/IP
- HTTP는 애플리케이션 계층 프로토콜로 자신의 메시지를 전달하기 위해 **TCP/IP에게 reliable한 전송**을 맡김
  `TCP`
  - 오류 없는 데이터 전송
  - 순서에 맞는 전달(데이터를 보낸 순서대로 받음)
  - 조각나지 않는 데이터 스트림
- `IP`
  - Internet protocol 주소와 포트번호를 사용해서 클라이언트와 서버간 커넥션을 맞아야한다.
  - 호스트명은 DNS에서 IP로 변환가능함 

### Telnet
- HTTP는 TCP/IP를 사용하고, 문자열 기반이라 키보드로 목적지의 TCP포트로 연결하고(귀찮은걸 대신해줌), 출력 포트를 화면으로 연결해줌

## 프로토콜 버전
### HTTP/0.9
- 간단한 HTML만을 받아오는 용도

### HTTP/1.0
- HTTP 헤더, 추가 메서드, 멀티미디어 객체를 처리

### HTTP/1.0+
- `Keep-alive` 커넥션 지원
- 가상 호스팅 및 프락시 연결 지원

### HTTP/1.1
- 더 복잡해진 웹 애플리케이션과 배포를 지원
- 현재 HTTP 버전

### HTTP/2.0
- 구글의 SDPY프로토콜 기반으로 성능개선을 위해 만드는 중

## 웹의 구성요소
### `프락시`
- 클라이언트와 서버사이에 위치한 중재자로 클라이언트의 모든 HTTP 요청을 받아 서버에 전달한다.
  - 보안을 위해 동작하고 요청과 응답을 필터링해서 초딩들 야동 막음

### `캐시`
- 자주 접근하는 찾는 것의 사본을 저장해두는 특별한 종류의 HTTP 프락시 서버임

### `게이트웨이`
- 다른 서버들의 중개자로 동작하는 서버로, HTTP 트래픽을 다른 프로토콜로 변환하기 위해 사용
- 본인은 자기 스스로가 리소스를 갖고 있는 실제 서버인 것 처럼 요청을 다뤄서, 클라이언트가 자신이 게이트웨이와 통신하고 있다는 사실을 알아채지 못함.

### `터널`
- 두 커넥션 사이에서 날 데이터를 열어보지 않고 그대로 전달해주는 HTTP 어플리케이션

### `에이전트`
- 사용자를 위해 HTTP요청을 만들어주는 클라이언트 프로그램
- 사람의 통제 없이 스스로 웹을 돌아다니며 HTTP 트랜잭션을 일으키고, 콘텐츠를 받아오는 자동화된 사용자 에이전트가 있음
  - 스파이더, 웹로켓 등
