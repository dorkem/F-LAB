### 개요
- `HTTP`: 인터넷의 배달원
- `HTTP 메시지`: 무언가를 담아 보내는 소포

## 메시지의 흐름
- `HTTP 메시지`는 HTTP APP간 주고받은 데이터의 블록으로 `클라이언트`, `서버`, `프락시` 사이를 흐름
- 메시지의 방향은 `인바운드`, `아웃바운드`, `업스트림`, `다운스트림`이 있다.
  - 인바운드: 클라이언트 → 서버
  - 아웃바운드: 서버 → 클라이언트
  - 다운스트림: 클라이언트 -(요청)→ 서버 -(응답)→ 클라이언트
  - 업스트림: 다운스트림의 흐름 속에서 다운스트림이 걸어왔던 곳

<br><br>

## 메시지 문법
### 요청
<메서드><요청URL><버전><br>
<헤더><br>
<br>

GET /test/hi.txt HTTP/1.1<br>

### 응답
<버전><상태코드><사유구절><br>
<헤더><br>
<br>
<엔티티 본문><br><br>

| 메시지 각 부분 | 메시지 |
|---|---|
|시작줄| HTTP/1.0 200 OK|
|헤더|Content-type: text/plain|
|-|Content-length: 19|

|본문|Hello, World! |


## 시작줄
### 메서드
- `GET`
  - 서버에서 리소스를 요청해서 어떤 문서를 가져온다.
- `HEAD`
  - GET처럼 동작하지만, 서버의 응답으로는 헤더만 돌려준다.
  - 리소스를 가져오지 않고 리소스의 변경여부, 개체 존재 유무, 그에 대한 타입등을 알 수 있음
- `POST`
  - 서버에 입력 데이터를 전송하기 위해 설계되었다.
  - HTML폼을 지원하기 위해 흔히 사용된다.
- `PUT`
  - 서버에 문서를 쓴다.
  - PUT /product_list.txt
- `TRACE`
  - 메시지가 프락시를 거쳐 서버에 도달하는 과정을 추적한다.
  - 클라이언트는 자신과 목적지 사이에 있는 모든 HTTP 애플리케이션의 요청/응답의 연쇄를 따라가며 자신이 보낸 메시지가 망가졌거나 수정되엇는지, 어떻게 변경되었는지 확인이 가능함
- `OPTIONS`
  - 서버가 어떤 메시지를 수행할 수 있는지 확인한다.
- `DELETE`
  - 서버에서 문서를 제거한다.
### 상태코드와 사유구절
**`100-199` 정보성 상태구절**
- `100` Continued
  - 클라이언트: 서버가 다루기 어려운 큰 엔터티를 보내지 않으려는 목적, 최적화용으로 사용해야함(남발하면 서버가 오다는건지 만다는건지 모름), 서버에서 응답을 받을 때 까진 보내지 말고 기다리면, 타임아웃 이후에 자동으로 보내짐
  - 서버: expect 헤더가 없는 요청에는 100 continued 보내지 마라(이미 클라이언트는 바디 보냈을 수도 있음 = 프로토콜 꼬임)
- `101` Switching Protocols
  - 서버가 프로토콜을 바꾸었다.

<br>

**`200-299` 성공 상태코드**
- `200` OK
  - 정상요청
- `202` Accepted
  - 요청은 받아들여졌지만 서버는 어떤 동작도 수행하지 않음
- `203` Non-Authoritative Information
  - 엔티티 헤더가 원래 서버가 아닌 사본에서 왔다.
- `204` No Content
  - 웹 브라우저를 새 문서로 이동시키지 않고 갱신하고자 할 때 사용
- `205` Reset Content
  - 브라우저에게 현재 페이지에 있는 HTML 폼에 채워진 모든 값을 비우라고 말한다.
- `206` Partial Content
  - 부분/범위 요청이 성공함
  - 응답은 `Content-Range`와 `Date` 헤더를 반드시 포함해야하고, `Etag`와 `Content-Location`중 하나의 헤더도 반드시 포함해야함

<br>
**`300-399` 리다이렉션 상태 코드**
- `300` Multiple Choices
  - 요청한 URL이 가리킬 수 있는 리소스가 여러 개라서, 서버가 후보 목록을 Location 헤더에 담아줌
  - ex) GET menu 하면 서버입장에선 `menu.jpg`, `menu.pdf`등
- `301` Moved Permanently
  - 요청한 URL이 옮겨졌을 때 사용한다. 응답은 현재 리소스가 위치하는 URL을 Location 헤더에 포함해야함
  - "영구이사" 느낌
- `302` Found
  - 301의 상태코드랑 같지만, 여기선 서버 공사중으로, "임시로" 변경된 페이지를 가르키는 목적으로 Location 헤더에 담아응답 
- `303` See Other
  - 클라이언트에게 리소스를 다른 URL에서 가져와야한다고 말해주는 것
  - Location 헤더에 새 URL응답 메시지가 포함
- `304` Not Modified
  - GET 같은 요청을 보냈을 때 리소스 수정사항이 없다면 수정되지 않았다는 사실을 응답으로 주고, 본문을 가지지 않음
- `305` Use proxy
  - 리소스가 반드시 프록시를 통해 접근되어야 함을 나타내기 위해 사용
  - Proxy 위치는 응답에 Location 헤더에 포함함
- `307` Temporary Redirect
  - 302랑 비슷
  
<br>
**`400-499` 클라이언트 에러 상태코드**
- `400` Bad Request
  - 클라이언트가 잘못된 요청을 보냈다.
- `401` Unauthorized
  - 사용자 인증을 해라
- `402` Payment Required
  - 현재는 사용하지 않지만 나중에 쓰일 가능성이 있음
- `403` Forbidden
  - 요청이 서버에 이해 거부됨(거절의 이유를 숨기고 싶을 때)
- `404` Not found
  - 서버가 요청한 URL을 찾을 수 없을 때 사용
- `405` Method Not Allowed
  - 그 메서드 못쓴다고 쓸 수 있는 메서드를 사용자에게 알려줌
- `406` Not Acceptable
  - 주어진 URL에 대한 리소스 중 클라이언트가 받아들일 수 없는 경우(요청에 Accept: json 이런식으로 보냈는데, 응답할 수 있는게 xml 뿐인 경우)
- `407` Proxy Authentication Required
  - 리소스에 대한 인증을 요구하는 프락시 서버를 이용
- `408` Request Timeout
  - 클라이언트 요청을 완수하기에 많은 시간이 걸리는 경우 응답을 끊을 때
- `409` Conflict
  - 리소스에 대해 일으킬 수 있는 몇몇 충돌이 생길 염려가 생길 때
- `410` Gone
  - 서버가 한 때 리소스를 갖고 있었지만 제거되었을 때
- `411` Length required
  - 서버가 요청 메시지에 Content-Length 헤더가 있을 것을 요구할 때
- `412` Precondition Failed
  - 클라이언트가 조건부 요청을 걸었지만 하나가 실패하였을 때(Expect 헤더를 포함했을 때)
- `413` Request Entity Too Large
  - 서버가 처리할 수 있는 범위를 넘어갔을 때
- `414` Request URL Too Long
  - 서버가 이해하거나 지원하지 않는 유형의 엔터티를 보냈을 때
- `415` Unsupported Media Type
  - 서버가 이해하거 지원하지 못하는 유형의 엔터티를 클라이언트가 보냈을 때
- `416` Requested Range Not Satisfiable
  - 요청에서 특정 메시지 리소스의 범위가 잘못됐을때
- `417` Expectation Failed
  - 요청에 포함된 Expect 요청 헤더에 서버가 만족시킬 수 없는 기대가 담겨있는 경우

**`500-599` 서버 에러 상태코드**
- `500` Internal Server Arror
  - 서버가 요청을 처리할 수 없게 만드는 에러를 만났을 때
- `501` Not Implemented
  - 클라이언트가 서버의 능력을 넘은 요청을 했을 때
- `502` Bad Gateway
  - 게이트웨이를 거쳐 서버에서 응답읇 받으려는데 거기서 특정 이유로 이상한 응답을 받았을 때
- `503` Service Unavailable
  - 현재 서버가 요청을 처리해줄 수는 없지만 나중에는 가능함을 의미
- `504` Gateway Timeout
  - 상태코드 408과 비슷하지만 다른 서버에게 요청을 보내고 응답을 기다리다 타임아웃이 발생한 게이트웨이나 프락시에서 온 응답이다.
- `505` Method Not Allowed
  - 서버가 지원할 수 없거나 지원하지 않으려고 하는 버전으로 된 요청을 받았을 때
