TCP에서 3-way와 4-way 핸드셰이킹의 내부 동작 과정을 패킷 레벨에서 상세히 설명하고, 각각이 필요한 이유와 실무에서 발생할 수 있는 장애 케이스를 예시와 함께 설명하세요.    •  TIME_WAIT 상태가 발생하는 정확한 이유와, 이 상태가 리눅스 시스템에서 리소스 고갈로 이어지는 시나리오를 설명하세요.    •  TCP 연결 종료 과정에서 발생할 수 있는 소켓 리소스 누수 문제를 운영체제 레벨에서 어떻게 진단하고 대응할 수 있는지 설명하세요.    •  TCP의 상태 전이 다이어그램에서 각 상태의 의미와 전이 조건을 설명하세요.    •  TCP 핸드셰이킹 과정에서 패킷 손실이 발생할 경우 재전송 및 상태 전이가 어떻게 처리되는지 설명하세요.    •  TCP 연결 종료 시 FIN_WAIT_2, CLOSE_WAIT, LAST_ACK, TIME_WAIT 상태의 차이와 실무 장애 사례를 설명하세요. HTTP 1.0의 Keep-Alive와 HTTP 1.1의 지속 커넥션(Persistent Connection) 차이점과, 프록시 및 중간 장비에서 발생할 수 있는 문제점, 그리고 HTTP/2, HTTP/3에서의 커넥션 관리 방식을 비교 설명하세요.    •  HTTP 1.1에서 파이프라이닝과 멀티플렉싱의 차이점과, 각각의 한계점에 대해 설명하세요.    •  Head-of-Line Blocking이 TCP와 HTTP 계층에서 각각 어떻게 발생하며, 이를 해결하기 위한 프로토콜별 접근 방식을 설명하세요.    •  HTTP/2의 스트림과 프레임 구조, 그리고 흐름 제어 메커니즘을 상세히 설명하세요.    •  HTTP/3(QUIC)에서 커넥션 관리와 재전송, 순서 보장 메커니즘이 어떻게 구현되는지 설명하세요.    •  HTTP 프록시 환경에서 Keep-Alive 미지원 프록시가 발생시키는 장애와, 이를 진단하고 우회하는 방법을 설명하세요. JPA에서 연관관계의 주인(Owner)을 지정하는 원리와, 잘못 지정했을 때 발생할 수 있는 데이터 불일치 및 성능 문제를 구체적인 예시와 함께 설명하세요.    •  양방향 연관관계에서 mappedBy 속성의 역할과, 잘못 사용했을 때 발생하는 쿼리 및 데이터 동기화 문제를 설명하세요.    •  JPA에서 연관관계 매핑 시 LAZY와 EAGER 로딩 전략의 차이와, 각각의 실무적 장단점을 설명하세요.    •  JPA에서 컬렉션 값 타입 매핑(Collection of Value Type) 시 발생할 수 있는 문제점과, 이를 해결하기 위한 설계 패턴을 설명하세요.    •  JPA에서 연관관계 변경 시 Dirty Checking과 Flush 타이밍이 어떻게 동작하는지 설명하세요.    •  JPA에서 연관관계의 주인 변경이 필요한 시나리오와, 이를 안전하게 처리하는 방법을 설명하세요. 인덱스 설계 시 카디널리티(Cardinality)와 복합 인덱스의 컬럼 순서가 쿼리 성능에 미치는 영향, 그리고 인덱스가 많은 테이블에서 발생할 수 있는 DML 성능 저하 원인을 설명하세요.    •  B-Tree 인덱스와 Hash 인덱스의 내부 구조와, 각각의 장단점 및 사용 시나리오를 설명하세요.    •  복합 인덱스에서 컬럼 순서가 쿼리 옵티마이저의 인덱스 선택에 미치는 영향과, 실제 실행 계획 분석 방법을 설명하세요.    •  인덱스가 많은 테이블에서 DML(INSERT/UPDATE/DELETE) 성능 저하가 발생하는 내부 원리를 설명하세요.    •  카디널리티가 낮은 컬럼에 인덱스를 생성할 경우 발생할 수 있는 문제점과, 이를 진단하는 방법을 설명하세요.    •  커버링 인덱스(Covering Index)와 인덱스 스캔 방식(Index Scan, Index Only Scan)의 차이와 실무 적용 사례를 설명하세요. 이벤트 소싱(Event Sourcing) 아키텍처의 원리와, 주문 도메인에 적용할 때의 장점과 단점, 그리고 상태 복구 및 감사(Audit) 시나리오를 상세히 설명하세요.    •  이벤트 소싱과 CQRS(Command Query Responsibility Segregation) 패턴의 차이와, 두 패턴을 결합할 때의 설계 고려사항을 설명하세요.    •  이벤트 소싱 환경에서 이벤트 저장소(Event Store)의 일관성 보장 및 장애 복구 전략을 설명하세요.    •  이벤트 소싱에서 스냅샷(Snapshot) 전략의 필요성과, 스냅샷 생성 및 적용 시 주의할 점을 설명하세요.    •  이벤트 소싱 기반 시스템에서 이벤트 순서 보장과 중복 처리(Deduplication) 문제를 해결하는 방법을 설명하세요.    •  이벤트 소싱을 적용한 주문 도메인에서 롤백 및 재처리(Replay) 시나리오를 상세히 설명하세요.
