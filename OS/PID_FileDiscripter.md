## PID와 파일 디스크립터

---

### 먼저 OS가 왜 필요한지

키보드를 누르면 아래와 같은 흐름이 일어난다.

```
키보드 → OS → 프로그램
```

키보드랑 프로그램이 직접 연결되지 않는다. 중간에 OS가 항상 끼어있다.

왜냐면 프로그램이 여러 개 동시에 실행되기 때문이다.

```
현재 실행중:
- 크롬
- 카카오톡
- 스프링 부트
- 메모장
```

프로그램들이 직접 키보드에 접근하면 서로 다 가져가려고 충돌이 난다. 그래서 OS가 교통정리를 한다.

```
키보드 눌림 → OS가 받음 → "지금 포커스는 크롬이네" → 크롬한테 전달
```

---

### PID (Process ID)

OS는 실행중인 프로그램 여러 개를 구분하기 위해 번호를 붙인다. **그 번호가 PID다.**

```
크롬        → 1001번
카카오톡    → 1002번
스프링 부트 → 1003번

kill 1003   # 1003번 프로세스 종료
```

---

### 파일 디스크립터 (File Descriptor)

프로그램은 하드웨어에 직접 접근하지 못하고 **무조건 OS한테 허락을 받아야 한다.**

허락을 받을 때마다 OS가 **창구 번호**를 준다. 그게 파일 디스크립터다.

```
키보드 입력 허락  → 0번 창구
화면 출력 허락    → 1번 창구
파일 열기 허락    → 3번 창구
네트워크 허락     → 4번 창구
```

프로그램은 이 번호로 OS한테 요청한다.

```
프로그램: "OS야 4번 창구에서 데이터 읽어줘"
OS: 네트워크에서 데이터 가져다 줌
```

---

### 한줄 요약

```
PID              = 프로그램 번호표
파일 디스크립터  = 그 프로그램이 OS한테 허락받은 창구 번호
```
