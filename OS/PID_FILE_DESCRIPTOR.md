## 🗂️ PID와 파일 디스크립터

### 프로그램 실행 → 프로세스 탄생 → PID 부여

- `chrome` 아이콘을 더블클릭하면 OS가 그 프로그램을 메모리에 올리고 실행합니다.
- 이 실행 중인 인스턴스가 **프로세스**고, 커널이 여기에 번호표를 붙여주는데 그게 **PID**입니다.
      - 크롬을 두 번 열면 프로세스가 두 개 생기고 PID도 각각 다릅니다. PID는 그냥 "이 프로세스가 나야" 하는 신분증입니다.

<br>

### 프로세스가 뭔가를 쓰려면 → 파일 디스크립터 발급

- 프로세스가 혼자 떠 있다고 아무것도 못 합니다.
- 파일을 읽거나, 네트워크로 데이터를 보내거나, 터미널에 글자를 출력하려면 **자원에 접근**해야 합니다.
- 리눅스에서 이 자원들, 즉 파일, 소켓, 파이프, 터미널 등을 전부 **파일**로 취급합니다.
- 그리고 프로세스가 그 자원을 "열면(open)" 커널이 **번호표를 하나 발급**해줍니다. 그게 **파일 디스크립터(FD)** 입니다.

- 프로세스가 태어날 때 기본으로 세 개가 자동 발급됩니다.
      - `FD 0` → 키보드 입력(`stdin`)
      - `FD 1` → 터미널 출력(`stdout`)
      - **FD 2** → 에러 출력(`stderr`)

- 이후 파일을 열거나 소켓을 만들 때마다 3, 4, 5... 번호가 새로 붙습니다.

<br>

### 실제 동작 흐름

```
프로세스가 open("data.txt") 호출
      ↓
커널이 "알겠어, 너한테 FD 3번 줄게"
      ↓
프로세스가 read(3, ...) 로 파일 읽기
      ↓
다 쓰면 close(3) 으로 반납
```

- 프로세스는 자원의 실제 위치나 구조를 몰라도 됩니다. 그냥 **번호(FD)만 들고 커널한테 "3번으로 읽어줘"** 하면 커널이 알아서 처리합니다.

<br>

### 일상적인 예시로 보면

- **터미널에서 `cat file.txt` 실행**
      1. cat 프로세스가 생성되면서 `PID` 부여
      2. `file.txt`를 열면서 `FD 3` 발급
      3. `FD 3`으로 내용 읽기
      4. `FD 1`(`stdout`)로 터미널에 출력
      5. 프로세스 종료, FD 반납

- **크롬이 유튜브 영상 로딩**
      1. 서버에 `TCP 소켓` 연결
      2. FD 발급
      3. 그 FD로 데이터 수신
      4. 영상 캐시 파일 저장할 때 또 FD 발급
      5. 탭 닫으면 관련 FD 전부 반납

- **`|` 파이프 사용 (`ls | grep txt`)**
      1. ls 프로세스와 grep 프로세스 각각 생성, PID 두 개
      2. 둘 사이에 파이프(pipe)라는 자원 생성
      3. ls의 `FD 1`(stdout)이 파이프 입구를 가리키고
      4. grep의 `FD 0`(stdin)이 파이프 출구를 가리킴
      5. ls가 `FD 1`로 쓰면 grep이 `FD 0`으로 읽음

### 한 줄 정리

**PID는 "누가 실행 중인가"의 신분증, FD는 "그 프로세스가 지금 뭘 붙잡고 있는가"의 번호표.** 프로세스는 자원을 직접 건드리는 게 아니라 항상 FD라는 번호를 통해 커널한테 대신 해달라고 요청하는 구조입니다.
