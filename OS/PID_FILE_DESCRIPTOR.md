## OS, 프로세스, PID, 파일 디스크립터, 시그널 정리

**### 요약
- 리눅스에서 커널은 모든 자원(소켓, 파일, 파이프 등)을 직접 관리해요.
- 프로세스가 실행되면 커널은 그 프로세스에 PID를 붙여서 식별해요.
- 프로세스가 자원을 사용하고 싶으면 직접 접근할 수 없으니까 커널한테 시스템 콜로 부탁해요.
- 커널이 그 요청을 받아서 자원을 열어주고 번호(파일 디스크립터)를 발급해줘요.
- 그 다음부터 프로세스는 그 번호로 커널한테 "이 번호 자원 읽어줘, 써줘" 부탁하는 거예요.
- 자원은 항상 커널 공간에 있고 프로세스는 번호표만 들고 있는 거예요.

```
커널
├── 프로세스 테이블
│   ├── PID 1234 → nginx 프로세스
│   └── PID 1235 → 다른 프로세스
│
└── 자원들 (소켓, 파일, 파이프 등)
        ↑
        │  파일 디스크립터로 접근
        │
nginx 프로세스 (PID 1234)
├── 파일 디스크립터 3 → 소켓 (유저A)
├── 파일 디스크립터 4 → 소켓 (유저B)
└── 파일 디스크립터 5 → 로그 파일
```

---

### OS가 왜 필요한가

키보드를 누르면 아래와 같은 흐름이 일어난다.

```
키보드 → OS → 프로그램
```

- 키보드랑 프로그램이 사이에 OS가 껴있음.
- 프로그램은 여러 개 동시에 실행되기 때문이다. 중간에 OS가 항상 끼어있다.

```
현재 실행중:
- 크롬
- 카카오톡
- 스프링 부트
- 메모장
```

```
키보드 눌림 → OS가 받음 → "지금 포커스는 크롬이네" → 크롬한테 전달
```

---

### PID (Process ID)

- OS는 프로세스 들을 구분하기 위해 번호를 붙이는데 그게 PID임

```
크롬        → 1001번
카카오톡    → 1002번
스프링 부트 → 1003번

kill 1003   # 1003번 프로세스 종료
```

---

### 파일 디스크립터 (File Descriptor)

- 리눅스에서 파일, 소켓, 파이프 등 열려있는 모든 것에 붙는 번호이다.

```
키보드 입력 허락  → 0번 창구
화면 출력 허락    → 1번 창구
파일 열기 허락    → 3번 창구
네트워크 허락     → 4번 창구
```

프로그램은 이 번호로 OS한테 요청한다.

```
프로그램: "OS야 4번 창구에서 데이터 읽어줘"
OS: 네트워크에서 데이터 가져다 줌
```

### SIGTERM vs SIGKILL

```
SIG  = Signal (신호)
TERM = Terminate (절차에 따라 종료)
KILL = Kill (즉시 제거)
```

**SIGTERM (kill -15)** 은 OS가 프로세스한테 "정리하고 종료해줘" 라고 요청하는 것이다.

```
OS: "스프링아, 종료해줘" (SIGTERM)
스프링: "알겠어, 요청 마저 처리하고
         DB 연결 끊고
         파일 디스크립터 닫고 종료할게"
```

**SIGKILL (kill -9)** 은 OS가 프로세스를 정리할 틈도 없이 즉시 제거하는 것이다.

```
OS: (아무 말 없이 그냥 프로세스 제거)
스프링: (미처 정리도 못하고 그냥 죽음)

- 처리중이던 요청 날아감
- DB 연결 제대로 못 끊음
- 파일 디스크립터 그냥 남음
```

그래서 **SIGTERM 먼저 시도하고, 안 죽으면 SIGKILL을 쓰는 것**이 일반적이다.

### 부모-자식 프로세스

프로세스는 작업이 많아지면 자식 프로세스를 만든다.

```
스프링 부트 (부모)
    └── 요청 처리 (자식1)
    └── 요청 처리 (자식2)
    └── 요청 처리 (자식3)
```

자식이 작업을 끝내고 죽으면 OS한테 종료코드를 전달한다.

```
"나 정상적으로 끝났어 (0)"
"나 오류로 끝났어 (1)"
```

OS가 부모한테 알리고, 부모가 보고를 받아야 OS가 자식 정보를 완전히 삭제한다.

---

### 좀비 프로세스

자식은 죽었는데 **부모가 보고를 안 받은 상태**다.

```
자식: 작업 끝, 죽음
부모: 보고 안 받음 (바쁘거나 버그)
결과: 자식은 죽었지만 PID가 남아있음 → 좀비 프로세스
```

좀비가 쌓이면 PID를 다 차지해서 새 프로세스 생성이 불가능해진다.

---

### 고아 프로세스

**부모가 먼저 죽어서 혼자 남은 자식 프로세스**다.

```
부모: SIGKILL 맞고 즉시 제거
자식: 혼자 남아서 작업 계속 → 고아 프로세스
```

OS는 고아를 그냥 두지 않고 **init (PID 1번) 이 입양**한다.

```
init (PID: 1)
    └── 고아 프로세스 (PID: 1001) ← 입양됨
```

---

### 한눈에 정리

```
PID              = 프로그램 번호표
파일 디스크립터  = OS한테 허락받은 창구 번호

SIGTERM          = "정리하고 종료해줘" 요청
SIGKILL          = OS가 그냥 강제 즉시 제거

좀비 프로세스    = 자식은 죽었는데 부모가 보고를 안 받은 상태
고아 프로세스    = 부모가 먼저 죽어서 혼자 남은 자식 프로세스
```**
