# MySQL과 MariaDB의 관계
- MySQL의 창시자는 오라클의 MySQL 인수에 화가나서 그대로 갖고와서 만든게 `MariaDB`임

## 오라클과 MySQL과의 구조적 차이
### 오라클(통합 스토리지)
- DB 서버들이 통합된 물리적인 스토리지를 `공유`한다.
- 저장소가 하나라서 데이터가 꼬이지 않는다.
- 데이터를 복사하는 시간이 필요 없어서, DB 서버만 키우면 서비스를 키울 수 있다.(하지만 입구는 한 개라서 병목현상이 발생할 수 있음)
- 저장소가 한개라 저장소 자체가 고장나면 전체 시스템이 죽는 `Single Point of Failure`과, 접속자가 몰리면 하나의 통로로 몰리기 때문에 네트워크 속도가 느려지는 `병목현상` 발생
- 서버간 데이터 충돌을 막는 하드웨어가 필요해서 비용이 비쌈

### MySQL의 (Master-Slave/Replication)
- `Master`: "쓰기 전용". `CUD`를 담당함
- `Slave`: "읽기 전용". Master의 데이터를 로그를 통해 복제받아 보관하며, 사용자의 `R`을 처리
- 나누는 이유
  - 보통 앱에는 읽는 사람이 더 많으므로, 마스터 서버가 CRUD를 100% 다 하지않고, 읽기작업을 여러 슬레이브로 나눠서 처리함(`쿼리오프로딩`)
  - 마스터가 불타도, 슬레이브를 마스터로 승격시켜서 서비스를 이어서 할 수 있게됩니다.
  - (`Orchestrator`가 장애감지, 슬레이브 상태 확인, 스토리지에 로그들을 슬레이브에 반영, 승격, 나머지 슬레이브가 마스터를 바라보도록 재구성하는 과정)
- 마스터 DB 접속은 `@Transactional`, 슬레이브 DB 접속은 `@Transactional(readOnly = true)`
- 데이터 변경이 잦으면 마스터에서 슬레이브로 보내는 로그 관리가 힘들고, 마스터가 죽었을때 장애 복구 시 복잡해지는 경우가 있다.
