# 트랜잭션과 잠금
## 5.1 트랜잭션
### 스토리지 개요
- `InnoDB` 스토리지 엔진: 트랜잭션 제공 O
- `MyISAM`, `MEMORY` 스토리지 엔진: 트랜잭션 제공 X → 정합성이 떨어짐

### 락
- `MySQL 엔진락`: 스토리지 엔진 락에 영향을 줌
  - 글로벌 락
    - 서버에 존재하는 모든 테이블을 닫고 잠금을 건다.(비용도 높고 작업도 멈춰야 함)
    - DB에 존재하는 MyISAM, MEMORY 스토리지 엔진의 테이블에 대해 mysqldump로 일관된 백업을 받아야할 때 글로벌 락을 사용(InnoDB에서는 백업 락이라는게 도입되었다. 백업 시 레플리카 서버에서 글로벌 락을 획득해서 진행함)
  - 테이블 락
    - 테이블에 거는 락으로 명시적, 묵시적인 락을 검
    - 묵시적 락은 쿼리가 실행되는 동안 자동으로 획득됐다가 쿼리가 완료한 후 자동해제(InnoDB에서는 **레코드 기반 잠금**이기 때문에 묵시적인 테이블락이 걸리지 않음, DDL에만 영향을 줌)
  - 메타 데이터 락
  - 네임드 락
- `스토리지 엔진락`:
  - 레코드 락
  - 갭 락
  - 넥스트 키 락
  - 자동 증가 락
