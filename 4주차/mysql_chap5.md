# 트랜잭션과 잠금
## 5.1 트랜잭션
### 스토리지 개요
- `InnoDB` 스토리지 엔진: 트랜잭션 제공 O
- `MyISAM`, `MEMORY` 스토리지 엔진: 트랜잭션 제공 X → 정합성이 떨어짐

### 락
- `MySQL 엔진락`: 스토리지 엔진 락에 영향을 줌
  - 글로벌 락
    - 서버에 존재하는 모든 테이블을 닫고 잠금을 건다.(비용도 높고 작업도 멈춰야 함)
    - DB에 존재하는 MyISAM, MEMORY 스토리지 엔진의 테이블에 대해 mysqldump로 일관된 백업을 받아야할 때 글로벌 락을 사용(InnoDB에서는 백업 락이라는게 도입되었다. 백업 시 레플리카 서버에서 글로벌 락을 획득해서 진행함)
  - 테이블 락
    - 테이블에 거는 락으로 명시적, 묵시적인 락을 검
    - 묵시적 락은 쿼리가 실행되는 동안 자동으로 획득됐다가 쿼리가 완료한 후 자동해제(InnoDB에서는 **레코드 기반 잠금**이기 때문에 묵시적인 테이블락이 걸리지 않음, DDL에만 영향을 줌)
  - 네임드 락
    - 사용자가 지정한 문자열에 대해 획득하고 반납(해제)하는 잠금
    - 배치 프로그램 처럼 한번에 많은 레코드를 변경해야하는 쿼리에 네임드락 사용하면 간단히 해결 가능
  - 메타데이터 락
    - 테이블 데이터에 거는게 아닌 테이블 정의 자체(컬럼정보, 인덱스정보, 제약조건, 테이블 속성)에 거는 락
    - Online은 메타데이터 락(MDL) 때문에 서비스가 멈추는 문제를 줄이려고 나온 기술
      - ```
        📝 사전 지식
        	•	UPDATE / INSERT는 레코드 락 (MDL Read Lock)
        	•	ALTER TABLE은 MDL Write Lock
        	•	MDL은 “정의(설계도)”를 보호하는 락
        
        🍀 온라인 DDL
         ALTER TABLE 요청
        → MySQL 엔진: MDL Write 요청
        → (기존 UPDATE/INSERT 끝날 때까지 대기)
        → MDL Write 획득 (아주 잠깐)
        → 테이블 정의 변경 준비
        → MDL Write 해제
        → (백그라운드 DDL 작업 진행)
        → 다시 MDL Write 획득 (아주 잠깐)
        → 새 테이블 정의로 스위치
        → MDL Write 해제

        🍀 그 사이에 DML동작 
         UPDATE/INSERT 요청
        → MDL Read 획득
        → (DDL 중이지만 정의는 일관됨)
        → 레코드 락 획득
        → 데이터 변경
        → COMMIT
        → MDL Read 해제
        ```
      - DDL의 ‘제어’는 단일 스레드라서, 구조 변경을 완성하려면 모든 행을 다시 써야 해서 오래걸림. 따라서 그 작업을 pk기준으로 내부적에서 병렬로 처리한다.
