## 인덱스
## 8.1 디스크 읽기 방식
### 개요
- 데이터베이스의 성능 튜닝은 어떻게 디스크의 I/O로 줄이느냐가 중요함
- CPU나 메모리등 전기적 특성을 띈 장치는 발전했지만, 디스크같은 기계식 장치의 성능은 제한적으로 발전됨
  - 디스크 원판에 의존하는 HDD(병목이 심함)보다는 요즘 SSD(전자식 저장매체)+플래시 메모리가 활용하고 있음

## 8.1.2 랜덤 I/O와 순차 I/O
- 디스크 원판을 돌려서 읽어야 할 데이터가 저장된 위치(디스크 헤더를 옮겨서 읽어야함)
  - 랜덤 I/O
    - 요청 3번에 디스크 헤더 3번
    - 보통 인덱스 범위 스캔에 사용
    - 디스크가 읽는 위치가 연속적이지 않아서 랜덤이라고 쓴거임
  - 순차 I/O
    - 요청 3번에 디스크 헤더 1번 (디스크 헤더를 얼마나 적게 옮기는가가 관건이므로 더 빠름)
    - 큰 테이블의 레코드를 대량으로 읽을 때 사용

## 8.2 인덱스
- 인덱스 컬럼 값을 주어진 순서로 미리 정렬해서 보관
- `Sorted List`
  - DBMS 인덱스 자료구조로 저장할 때 항상 정렬해서 저장함
  - 인덱스는 Insert/Update/Delete 성능을 희생해서 Select속도를 높인다.
- `Array List`
  - 데이터파일에 값을 저장하는 순서 그대로 저장(접근이 O(1)이라 그런 것 같음)
