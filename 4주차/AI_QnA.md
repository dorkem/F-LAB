## 오늘 내용에 맞춰진 질문들
### 트랜잭션 격리 레벨 4가지(Read Uncommitted, Read Committed, Repeatable Read, Serializable)의 내부 동작 방식과 각 레벨에서 발생할 수 있는 현상(더티 리드, 논리피터블 리드, 팬텀 리드 등)을 상세히 설명하세요.    
- MVCC 기반 DBMS에서 Repeatable Read와 Serializable의 구현 차이점은 무엇이며, 각각의 성능 및 일관성 트레이드오프를 설명하세요.
- 이노DB에서 팬텀 리드를 방지하기 위한 갭 락(Gap Lock)의 동작 원리와 실제 쿼리 실행 시 발생할 수 있는 문제 상황을 예시와 함께 설명하세요.
- 트랜잭션 격리 레벨 변경이 대규모 트래픽 환경에서 시스템 성능과 장애 발생에 미치는 영향을 분석하세요.
- Read Committed와 Repeatable Read 환경에서 언두 로그의 역할과 관리 방식의 차이를 설명하세요.
- 트랜잭션 격리 레벨이 애플리케이션 아키텍처(예: CQRS, 이벤트 소싱)에 미치는 영향과 고려사항을 논의하세요.

### MVCC(Multi-Version Concurrency Control)와 언두 로그(undo log)의 관계 및 InnoDB에서의 구현 방식을 설명하세요.
- MVCC 환경에서 언두 로그가 지속적으로 쌓일 때 발생할 수 있는 메모리/스토리지 이슈와 이를 해결하기 위한 GC(가비지 컬렉션) 전략을 설명하세요.
- MVCC가 적용된 DBMS에서 롱런 트랜잭션이 시스템에 미치는 영향과 이를 최소화하기 위한 실무적 방안을 제시하세요.
- MVCC와 락 기반 동시성 제어 방식의 근본적 차이와 각 방식의 장단점을 비교하세요.
- InnoDB에서 언두 로그와 리두 로그의 역할 차이와 장애 복구 시나리오에서의 활용 방식을 설명하세요.
- MVCC 환경에서 스냅샷 일관성(snapshots consistency)을 보장하는 내부 메커니즘을 상세히 기술하세요.

### 이노DB(InnoDB)에서 클러스터링 인덱스와 보조 인덱스의 구조적 차이와 각각의 장단점을 설명하세요.
- 클러스터링 인덱스 구조가 데이터 삽입/삭제/갱신 시 성능에 미치는 영향과 이를 최적화하기 위한 전략을 설명하세요.
- 보조 인덱스(Secondary Index)에서 인덱스 커버링(Index Covering)과 인덱스 스캔의 차이점을 설명하고, 쿼리 최적화에 어떻게 활용할 수 있는지 논의하세요.
- 클러스터링 인덱스가 없는 DBMS(예: MyISAM)와 InnoDB의 인덱스 구조 차이가 데이터 일관성과 성능에 미치는 영향을 비교하세요.
- 복합 인덱스(Composite Index) 설계 시 고려해야 할 점과 실제 쿼리 패턴에 따른 인덱스 설계 전략을 설명하세요.
- 대용량 테이블에서 인덱스 재구성(Rebuild) 작업이 시스템에 미치는 영향과 무중단 인덱스 관리 방안을 논의하세요.

### 트랜잭셔널 어노테이션(@Transactional)이 내부적으로 동작하는 원리와 AOP, 커넥션 관리, 커밋/롤백 처리 과정을 상세히 설명하세요.
- 스프링 프레임워크에서 프록시 기반 AOP와 AspectJ 기반 AOP의 차이와 @Transactional 적용 범위의 차이를 설명하세요.
- 트랜잭셔널 어노테이션이 중첩 트랜잭션(Nested Transaction)이나 Propagation 옵션에서 어떻게 동작하는지 설명하세요.
- 트랜잭셔널 어노테이션이 적용된 서비스에서 예외 발생 시 롤백 정책의 커스터마이징 방법과 실무 적용 사례를 설명하세요.
- JPA 환경에서 트랜잭션 동기화와 영속성 컨텍스트 관리의 관계를 상세히 설명하세요.
- 트랜잭셔널 어노테이션이 멀티 데이터소스 환경에서 동작할 때 발생할 수 있는 문제점과 해결 방안을 논의하세요.

### SOLID 원칙 각각(SRP, OCP, LSP, ISP, DIP)의 정의와 실무 설계에서의 적용 예시를 설명하세요.
- OCP(개방-폐쇄 원칙)와 DIP(의존성 역전 원칙)가 실제 대규모 시스템에서 어떻게 상호 보완적으로 적용되는지 설명하세요.
- LSP(리스코프 치환 원칙) 위반이 발생하는 대표적인 사례와 이를 방지하기 위한 설계 패턴을 논의하세요.
- ISP(인터페이스 분리 원칙) 적용 시 인터페이스 세분화가 지나치게 이루어질 때 발생할 수 있는 문제점과 균형점에 대해 설명하세요.
- SRP(단일 책임 원칙)와 응집도의 관계를 실제 코드 예시와 함께 설명하세요.
- SOLID 원칙이 마이크로서비스 아키텍처 설계에 미치는 영향과 적용 시 고려사항을 논의하세요.
