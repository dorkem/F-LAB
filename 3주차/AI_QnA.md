### 스프링 프레임워크에서 DI와 IOC의 차이점과 각각의 역할을 상세히 설명하세요.

- 스프링의 Bean 생명주기와 DI/IOC가 어떻게 연관되는지 설명해보세요.
- DI와 IOC를 활용할 때 발생할 수 있는 순환 참조 문제와 그 해결 방법을 설명하세요.

- 스프링에서 프로토타입 스코프 빈의 DI/IOC 동작 방식과 싱글톤 스코프와의 차이점을 설명하세요.
- 스프링 DI에서 Setter Injection, Constructor Injection, Field Injection의 장단점과 내부 동작 차이를 설명하세요.

### JDK 다이나믹 프록시와 CGlib 프록시의 차이점과 각각의 내부 동작 원리를 설명하세요.   
- JDK 다이나믹 프록시가 생성하는 프록시 객체의 클래스 구조와 메서드 호출 흐름을 바이트코드 수준에서 설명하세요.  
- CGlib이 바이트코드를 조작하여 프록시를 생성하는 과정과, 클래스 상속 기반 프록시의 한계점에 대해 설명하세요.  
- 스프링 AOP에서 JDK 다이나믹 프록시와 CGlib이 선택되는 기준과, 각각의 프록시가 적용되는 실제 사례를 설명하세요. 
- 프록시 객체에서 내부 메서드 호출(self-invocation) 시 AOP가 적용되지 않는 이유와 이를 우회하는 방법을 설명하세요. 
- JDK 다이나믹 프록시와 CGlib 프록시의 성능 차이와, 대규모 서비스에서의 선택 기준을 설명하세요.  
- 프록시 패턴이 스프링 트랜잭션 처리에 미치는 영향과, 트랜잭션 경계 설정 시 주의할 점을 설명하세요. 

### 스프링 트랜잭션 어노테이션(@Transactional)이 다양한 ORM/SQL 매퍼(JPA, MyBatis 등)에서 일관되게 동작할 수 있는 구조적 원리를 설명하세요.
- 플랫폼 트랜잭션 매니저(PlatformTransactionManager) 인터페이스의 주요 메서드와 각 ORM/매퍼별 구현체의 차이점을 설명하세요.   
- 트랜잭션 동기화(Transaction Synchronization)가 ThreadLocal을 통해 어떻게 구현되는지, 실제 커넥션 객체의 흐름을 설명하세요.    
- 스프링 트랜잭션 전파 속성(Propagation)별로 트랜잭션 경계가 어떻게 설정되는지, 내부적으로 어떤 로직이 실행되는지 설명하세요.    
- 트랜잭션 어노테이션이 프록시 기반으로 동작할 때, 내부 메서드 호출 시 트랜잭션 경계가 깨지는 이유와 해결책을 설명하세요.   
- 트랜잭션 매니저가 커밋/롤백을 수행할 때, DB 커넥션과 세션, 자원 해제 과정이 어떻게 처리되는지 설명하세요.   
- 스프링 트랜잭션 관리에서 멀티 데이터소스 환경에서의 트랜잭션 일관성 보장 방법을 설명하세요. 

### ThreadLocal이 스프링 트랜잭션 관리에서 어떻게 활용되는지, 그 한계와 주의사항을 포함하여 설명하세요. 
- ThreadLocal의 생명주기와 GC(가비지 컬렉션) 관점에서 발생할 수 있는 메모리 릭 문제와 그 해결 방법을 설명하세요.  
- ThreadLocal을 활용한 트랜잭션 동기화가 멀티스레드 환경에서 발생할 수 있는 문제점과, 이를 해결하기 위한 대안(예: Reactor, Coroutine 등)을 설명하세요.   
- 스프링 트랜잭션에서 ThreadLocal을 통한 커넥션 관리가 비동기/논블로킹 환경에서 어떻게 동작하는지 설명하세요.  
- ThreadLocal을 활용한 트랜잭션 동기화와 DB 커넥션 풀(HikariCP 등)과의 상호작용을 설명하세요.   
- ThreadLocal을 이용한 트랜잭션 동기화가 서블릿 컨테이너의 Thread Pool 환경에서 발생할 수 있는 문제와, 이를 방지하는 스프링의 내부 처리 방식을 설명하세요. 

### 데이터베이스 정규화의 단계별(1NF, 2NF, 3NF 등) 원칙과, 정규화가 성능에 미치는 영향 및 실무에서의 트레이드오프를 설명하세요.    
- 정규화와 반정규화(De-normalization) 전략을 실무에서 적용할 때 고려해야 할 요소와 사례를 설명하세요.   
- 정규화로 인한 조인(Join) 성능 저하 문제를 해결하기 위한 인덱스 설계 및 쿼리 최적화 방법을 설명하세요.
- NoSQL 환경에서 정규화 개념이 어떻게 적용되거나 무시되는지, 그 이유와 사례를 설명하세요.   
- 정규화 단계별(1NF~3NF)로 인한 데이터 무결성 보장 방식과, 트랜잭션 처리와의 연관성을 설명하세요.
- 정규화된 테이블 구조에서 대용량 데이터 처리 시 발생할 수 있는 병목 현상과 그 해결 방안을 설명하세요.

### DB 인덱스의 내부 구조(B-Tree 등)와 인덱스가 검색/쓰기 성능에 미치는 영향, 그리고 인덱스 설계 시 고려해야 할 점을 설명하세요.  
- B-Tree와 Hash 인덱스의 구조적 차이와 각각의 장단점을 설명하세요.    
- 복합 인덱스(Composite Index)와 커버링 인덱스(Covering Index)의 개념과 활용 사례를 설명하세요.  
- 인덱스가 대량의 데이터 삽입/삭제 시 성능에 미치는 영향과, 인덱스 유지 비용을 최소화하는 전략을 설명하세요.   
- 인덱스 스캔(Full Index Scan)과 테이블 스캔(Full Table Scan)의 차이와, 옵티마이저가 인덱스를 선택하는 기준을 설명하세요.
- 인덱스 설계 시 Null 값, 중복 값, 정렬 순서 등이 성능에 미치는 영향을 설명하세요. 

### DB 락(리드락, 라이트락 등)의 동작 원리와, 트랜잭션 격리 레벨에 따른 락의 범위 및 동시성 제어 방식을 설명하세요.
- 트랜잭션 격리 레벨별(READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE)로 발생 가능한 동시성 이슈(Dirty Read, Phantom Read 등)를 설명하세요.    
- DBMS별(예: MySQL, Oracle)로 락 구현 방식과 트랜잭션 격리 레벨의 차이를 설명하세요.    
- 락 에스컬레이션(Lock Escalation) 현상과, 대용량 트랜잭션 처리 시 발생할 수 있는 문제점 및 해결책을 설명하세요.  
- 인덱스 락, 테이블 락, 레코드 락의 차이와 각각의 적용 사례를 설명하세요.    
- 락 대기(Deadlock) 상황이 발생하는 원인과, DBMS가 이를 감지하고 해결하는 내부 메커니즘을 설명하세요.
